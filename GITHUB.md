# Бесплатный запуск на GitHub Actions

Эта папка — содержимое отдельного публичного репозитория. Не загружайте
родительскую папку с другими личными файлами. Публичными будут только исходники.
Токен, chat ID и `data/config.json` публиковать не нужно.

1. Создайте Telegram-бота: https://t.me/BotFather → `/newbot`.
2. Локально из этой папки выполните `python3 bot.py setup` (без установки библиотек).
   Введите токен в скрытое поле и отправьте одноразовую команду своему боту.
   В файле `data/config.json` появятся token и chat_id; не отправляйте этот файл никому.
3. Создайте отдельный **public** репозиторий на https://github.com/new.
   Загрузите файлы этой папки, включая `.github/workflows/tickets.yml`.
   При загрузке через браузер скрытая папка может не попасть в загрузку:
   создайте файл `.github/workflows/tickets.yml` через Add file → Create new file
   и вставьте содержимое соответствующего локального файла.
4. В репозитории: Settings → Secrets and variables → Actions → New repository secret.
   Добавьте `TELEGRAM_BOT_TOKEN` (поле token из config.json)
   и `TELEGRAM_CHAT_ID` (поле chat_id). Значения вставляйте без кавычек.
5. Во вкладке Actions выберите Check IEM tickets → Run workflow.
   Успех — зелёный запуск и первое сообщение с текущим статусом в Telegram.
   Если ESL блокирует серверы GitHub, запуск будет красным: мониторинг не считается
   работающим, нужно разобрать ошибку. Проверка с GitHub выполнена вручную; отдельно убедитесь, что появился запуск с событием schedule.

Расписание задано каждые 5 минут (0, 5, 10…55). Проверьте появление запусков schedule:
успешный ручной запуск сам по себе не подтверждает работу расписания.
Сообщения со статусом — при первом успешном запуске и после 09:00, 15:00, 21:00
Europe/Berlin. Отдельные сообщения — при изменении статуса и ошибках проверки.
Не запускайте одновременно Docker-вариант и Actions: сообщения будут дублироваться.

## Ограничения бесплатного варианта

- Стандартные GitHub-hosted runners бесплатны в публичных репозиториях.
  Не выбирайте платные larger runners.
- Планировщик допускает задержки и пропуски; это не гарантия обнаружения за 5 минут.
- Через 60 дней отсутствия активности GitHub отключает расписание публичного
  репозитория. Периодически проверяйте Actions; при отключении включите workflow снова.
- Предыдущий статус хранится в кэше GitHub. Кэш может быть удалён: тогда возможен
  повтор текущего уведомления. Там нет токена, chat ID или личных данных.
- Ошибки до запуска Python (например, установки браузера) видны в Actions,
  но бот в таком случае не сможет сообщить о них через Telegram.
- Отслеживается кнопка продажи на ESL; остатки на конкретный день в Vivenu
  не проверяются. Обхода капчи или блокировки нет.

Документация: https://docs.github.com/en/actions/concepts/billing-and-usage
и https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule.

Любое сообщение в настроенном личном чате запрашивает ответ с результатом
свежей проверки. Ответ приходит на ближайшем запуске Actions (интервал 5 минут,
возможны задержки GitHub). Текст сообщений не сохраняется и не выводится в логи.
